# 2026-08-02 后续问题记录

## 问题 0：坐姿人物被错误抬高，随后旋转并碰倒周围物体

**状态：未修复。优先级：后续场景逻辑修复的第 0 个问题。**

### 现象

在用户自己的 `cam_22_foreground_run1` 场景中，原图里人物坐在椅子上；但 Stage 2/Stage 3 的结果中，人物从初始帧就明显悬空，脚甚至位于椅背最高点附近。进入物理仿真后，人物会发生大幅位移和旋转，并可能撞翻桌面物体或椅子。

之前曾把下面这组数值解释成“基本符合坐在椅子上”，这个判断是错误的：

- 椅子整体最高点：约 `0.438932 m`；
- 人物整体最低点：约 `0.443932 m`；
- 两者间隔：约 `5 mm`。

椅子的整体最高点是椅背顶部，不是座面；人物的整体最低点通常是脚底。因此，这组数值实际证明的是“人物脚底被放到了椅背顶部上方约 5 mm”，绝不代表人物坐在座面上。

### 已确认根因

Stage 2 的场景树将人物记录为：

```text
person_sitting_behind_the_desk_000
  -- on --> black_mesh_office_chair_behind_the_desk_000
```

但 `scripts/infer_scene3d.py` 的 `place_to_ground()` 对普通父子关系采用了过度简化的统一高度规则：

```python
target_min_y = max_y_after[parent] + 0.005
```

也就是把子物体的**整体最低点**放到父物体的**整体最高点**上方 `5 mm`。这个规则只适合“一个物体完整放在另一个物体最顶面上”的简单情况，无法表达人物坐在有椅背的椅子上、物体位于中间层板上、多接触点支撑等关系。

`git blame` 显示该规则来自迁移前的既有代码提交 `16799558`，不是 Isaac Lab backend、RTX 5090、CUDA、GPU PhysX 或 tensor pipeline 引入的兼容性问题。Isaac Lab 只是接收并模拟了已经错误的初始位姿。

### 为什么之后还会产生大幅旋转

人物在场景树中被标成 `movable`，进入 Stage 3 后按自由的动态刚体处理。错误高度使人物没有处于正确的座面支撑状态；重力、与椅子/桌子/小物体的碰撞以及 6-DoF 的自由运动会把初始位置错误放大成下落、旋转和连锁碰撞。

不过，必须通过保存的各阶段姿态逐级比较，确认“大旋转”最早出现在哪一步：

1. Stage 2 canonical pose；
2. Stage 3 局部 CEM 输出；
3. Stage 3 全局 CEM 输出；
4. replay 的 frame 0 和后续物理帧。

在完成这项逐级对比前，不要武断地把旋转归因于坐标系、四元数转换或 Isaac Lab；目前已经确定的是**初始悬空来自 Stage 2 的高度放置规则**。

### 修复原则

1. 不得针对“人物”“椅子”或当前 cam_22 的具体对象名硬编码。
2. 不能再把所有 `on` 关系都等价为“子对象最低点对齐父对象最高点”。需要用通用场景语义表达实际支撑面、接触区域和中间高度支撑，或在可信时保留重建得到的父子相对位姿。
3. 对静态场景重建，应通过通用物理角色/关系决定对象是动态、运动学或固定实体，而不是默认所有 `movable` 实体都作为完全自由刚体；具体策略需要与最终联合物理评估要求一起设计。
4. 修复前先加入诊断：导出每个阶段每个对象的位置、旋转、竖直范围和父子相对位姿，并标明首次发生异常的阶段。
5. 回归验证至少应检查：frame 0 不悬空、人物与合理支撑区域接触、姿态不发生非预期跳变、仿真期间不因错误初始化撞翻其他对象。
6. `output/cam_22_foreground_run1` 继续只读；所有诊断和重跑必须使用新的显式输出目录。

### 给下一次 Codex 会话的提醒

先解决或精确定位问题 0，再讨论调大 CEM 参数。更大的并行规模和迭代次数不会修复错误的初始几何关系，只会更昂贵地优化一个定义错误的问题。不要再把椅子整体最高点当作座面，也不要把该问题描述为 Isaac Lab 迁移或 GPU 兼容性故障。

## 问题 1：y_align 上方向选择错误导致物体整体倾斜（已修复）

**状态：已修复并合并进 main（fix/yalign-orientation，commit 321d32b；merge 76a891f）。**

### 现象

cam_40 场景（5 个物体）重建后，桌子、sneaker、U 形物体、鞋带全部歪斜：
- 桌子顶面法线不再是 +y，桌面呈约 45° 倾斜，放在桌上的物体全部滑落；
- 5 个物体里只有 blocky（立方体）碰巧是正的（cos_y≈0.999），其余 4 个 cos_y≈0.00~0.10。

### 已确认根因

`rest3d/utils/mesh.py` 的 y_align 用"OBB 轴中与**当前帧 y** 夹角最小者"作为上方向。但 SAM3D 重建的坐标系是相机相对系，其 y 轴与真实世界竖直方向没有任何保证；对有明显平坦顶面的物体（桌子、鞋、板子），该启发式经常选中水平长轴：

- 桌子：真实桌面法线是 OBB 的第 3 根轴，而选中"竖直"的那根轴与桌面法线夹角约 90°（cos≈0.01）；
- 修复前验证：桌子、sneaker、U 形、鞋带全部 cos_y≈0.00~0.04，仅 blocky 为 0.999。

### 修复内容

在 `rest3d/utils/mesh.py` 新增：

- `_dominant_face_direction()`：按面积加权聚类网格面法线（量化 + 贪心合并），求最大平坦区域的法线；无显著平坦面（面积占比 < 12%）返回 None；
- `_robust_up_direction()`：优先用最大平坦面法线作为上方向，无平坦面时回退到旧的 OBB-y 启发式；
- `align_bbox_to_y_up_from_axes()` 与 `get_scene_up_axis_from_ref_axes()` 均改为使用几何估计（场景级上方向也优先用各物体网格几何）。

### 验证

- 对 cam_40 缓存 raw mesh 重跑 y_align：5 个物体 + floor 全部 upright（cos_y≈1.0）；
- gym 后端全流程重跑 cam_40：全局 CEM reward 从 -0.56 改善到 -0.0246，局部组 reward 从 -11.24（pen=1）改善到 -0.72（pen=0）；
- 对照实验（A/B，均在 fix/scene-support-semantics 分支）：无修复 run1 `scene_stable=False`（3 个物体位移 0.19~0.32 m）；merge 修复后 run2 `scene_stable=True`（全部 ≤0.048 m）。

### 遗留 / 后续注意

- cam_22 的坐姿人物曾尝试"侧面/顶面判别"细化（commit 7f2c5cb：主平面法线偏离竖直 >60° 时回退 OBB-y），连同 kinematic 检查 float32 量化修复（7a7eba2）一起被**撤销**（revert c6c599f、c61457a），当前 main 只保留原始几何修复。后续若重新遇到人物类物体，需重新设计该判别并避免把最大平面（如后背）当作上表面。
- 当前 main 的 3_replay / CEM 检查仍按 fbbcc0e 状态。
