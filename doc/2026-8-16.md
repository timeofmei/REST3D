## 问题 0：整合形态——独立入口脚本，而不是改 infer_scene3d.py

原决策点 B 设想 `infer_scene3d.py` 加 `--mesh-backend sam3d|mix3r`。但现在明确了
mix3r 后端的输入形态与 sam3d 根本不同：多视角图像 + 每视角 mask + 相机标定，
而 `infer_scene3d.py` 整个结构是围绕"单图 + 单图 mask + SAM3D axes + scene_tree"
写的（y_align 依赖 SAM3D 输出的 axes，place_to_ground 依赖 Stage 1 的
scene_tree.json——这两样 mix3r 都没有，见问题 3）。

**定案（2026-08-16）**：新增 `scripts/infer_scene3d_mix3r.py` 作为独立入口，复用
`rest3d/utils/`（urdf、mesh、log）并按需新增模块；输出目录结构与 sam3d 后端
完全一致（`scene_raw/ scene_metric/ scene_canon/ urdf_files/`），Stage 3
（stable_scene、replay）零改动。"可切换对比"通过输出格式兼容实现，而非代码
开关。sam3d 主链路一行不动。

## 问题 1：D 路线的标定桥接——wand 标定 JSON 替代 COLMAP

已核实 `data/0810/calibration_results-20-0-21.json`：

- 80 台相机全覆盖（cam_1..cam_80，工作视点 49–80 都在内）；
- 每相机：fx/fy/cx/cy + 畸变（k1–k4, p1, p2）+ world2Cam（四元数+平移）；
  整体重投影 0.37 px，wand 误差 0；
- imageSize 3000×4096 与 `images/cam_NN.png` 实际尺寸一致（逐相机内参，fx 不同）。

与 d_smoke（COLMAP）的三个差异，D 路线实现必须处理：

1. **有畸变**：COLMAP PINHOLE 已去畸变，这里 mask 像素过射线前必须先去畸变
   （`cv2.undistortPoints`，逐相机参数）；
2. **无 points3D 点云**：d_smoke 的"从稀疏点云拟合地面/识别物体点"不可用，
   支撑面只能另想办法（问题 2）；
3. **世界系长度单位是毫米**：world2Cam 平移量级 ~2000–2300（已核实，对应
   2–3 m 半径采集架，米制解释不通）。fx/fy/cx/cy 是像素不受影响，但用这份
   标定三角化/拟合出的所有 3D 量（接触点、支撑面、h_real）都是 mm。
   约定：**标定加载器在读入时一次性 ÷1000 转米**，后续流程一律米制，
   不在求解器里散落换算。

**建议**：`rest3d/utils/` 新增标定加载模块（wand JSON → 每视点 K、c2w、
去畸变映射），自检方式：多视点 mask 底部中心射线三角化残差 + 接触点共面性
RMS（问题 2 的副产品直接当验收指标）。

## 问题 2：支撑面从哪来——多视点三角化自举（定案：所有物体视为放在地面）

**定案（2026-08-16）**：mask 里没有桌子，桌子也不进最终结果；**所有物体
视为直接放在同一支撑面上，该面即"地面"**。本期定位是初步实验，目标是把
全链路跑通，不处理叠放/悬空特例——u_shaped_handle 等若存在悬空部分，
接触点仍按 mask 底部处理，误差接受并在报告中记录。

方案（多视点三角化自举）：每对象取多视点 mask 底部中心像素 → 去畸变射线
→ 两两最小二乘三角化得接触点 → 4 对象接触点拟合公共支撑面（法向即世界
up，自检）；之后回退到 d_smoke 的"平面+射线"闭式高度解，多视点取中位数。
自校准、零先验、零新依赖。

否决的备选：高度常数（需知道 wand 世界系与真实地面的关系，目前未知）；
对 0810 跑 COLMAP（新依赖 + 重复劳动，标定已存在）。

## 问题 3：mix3r 网格的位姿——保留 Stage 1，D 路线只补 scale/yaw/水平位置（定案）

**定案（2026-08-16）**：**仍然跑 Stage 1**（单图 Gemini + SAM3，产出
scene_tree.json），mix3r 只替代 SAM3D 的网格生成。分工：**D 路线管每物体的
scale / yaw / 水平位置（x,z），tree（place_to_ground 原样复用）管 Y 方向
堆叠**。理由：sam3d 链路里所有物体网格出自同一次单图重建、天然共享场景
坐标，place_to_ground 只调 Y、水平位置是继承来的；mix3r 每物体是独立归一化
帧，尺度与水平位置必须由 D 接触点补上，而支撑关系语义仍由 tree 提供。

仍然成立的事实：mix3r 输出 `sample_mesh_perviewbias.ply` 为归一化尺度、
对象中心、**无 axes 概念**——y_align（依赖 SAM3D axes）不能直接用。替代：
网格侧取 PCA 最小轴为 up（本场景 4 物体皆为扁/低物体，容器
pca=[1.00, 0.52, 0.23]、盖 [1.00, 0.55, 0.11]，成立），符号用多视点 mask
判别哪面朝上；若某物体立放（如 u_shaped_handle）按 mask 高宽比换轴兜底。

D 求解（每物体独立）：

- **up**：PCA 最小轴（如上）；
- **yaw**：三角化质心方向 − 接触点方向定水平旋转；
- **尺度 s**：s = h_real（多视点闭式高度中位数）/ h_mesh（up 对齐后网格
  高度）；**每物体独立解**（8-11 已证明 mix3r 跨物体比例不可靠，不能共享
  因子）；
- **x/z**：接触点世界坐标；
- **Y**：不由 D 定，交回 place_to_ground 按 tree 装配。

三个衔接点（实现时处理）：

1. **对象命名对齐**：Gemini 的 tree 节点名需映射到多视点 mask 目录名
   （lunchbox_lid 等 4 个），否则 place_to_ground 找不到对应 obj；
   初步实验用手写映射表；
2. **tree 过滤**：特写场景下 Gemini 可能发现桌子/背景物体——按问题 4
   桌子不进结果，tree 过滤成只剩 4 个目标物体，失去支撑的节点挂到 floor；
3. **嵌套支撑与 D 自举的一致性**：若 tree 判定嵌套（如 lid 放在容器上），
   该物体 mask 底部三角化点会落在父物体顶面、污染共面拟合——按 tree 自底
   向上处理：先解 ground 物体，子物体改用父物体缩放后的顶面作支撑面
   （原 d 设计）。

未验证环节：Stage 1 未在 0810 数据上跑过——选一个 4 物体均可见的视点
（如 cam_73）冒烟，需 `.env` 的 Gemini key；低风险。

  假设每 actor 对 64 个接触，而本场景小物体 + 每件 8–16 个 VHACD 凸包 +
  初始穿插的接触密度远超该假设。**修复**：VHACD 场景的每对假设 64→128
  （`_pt`），重配 1,874,329 对（~457 MB GPU），重跑零溢出。
- **门禁结果**（log_global_scene_20260816_150520.log）：
  `stab=0.016, vel=0.013, pen=0`——与旧 sam3d 场景（stab=0.012）同量级，
  物理稳定；**layout=1.863**（旧场景 0.062）——CEM 为化解初始穿插大幅挪动
  了物体：盖 +15cm、双格容器 −11cm、**单格容器被抬高 2.8cm 摞到了把手顶上**
  （把手未动）。这是 mix3r 水平比例失真（凸包≈1.5×mask）导致初始穿插的
  物理化解，不是管线错误；代价是 D 路线的真实水平布局被部分覆盖。

## 问题记录（阶段 D 人工复查发现，2026-08-16 下午）

用户目检 viser 回放后发现两类问题：画面模糊、饭盒朝向与原图不符。排查
结论（本节只记录，修复随后分步进行）：

### P1 镜像 bug（确定性几何错误，修）

`solve_object_pose` 用 PCA 轴构造旋转 `R = E @ M.T`，其中 `M` 为 SVD 的
Vt 行向量基——**SVD 基的手性 det=±1 无保证**。实测 4 网格中 2 个
det(Vt)=-1（single_compartment_container、lunchbox_lid），对它们 R 是
**反射**而非旋转，网格被镜像。silhouette 打分发现不了（镜像 vs 正确
旋转 IoU 仅差 0.02，盒状物单侧弧轮廓几乎相同）。修复：构造时强制
det(M)=+1（det(Vt)<0 时翻转一行）。

### P2 方向（yaw）错误（修）

细粒度 yaw 扫描（固定 up、360°/5°，正确旋转基）显示脚印长轴锚定系统性
偏航：单格容器最佳 135°（锚定 0° 时 IoU 0.264 vs 0.373）、盖 245°
（0.061 vs 0.226）、把手 ~260°（0.022 vs 0.062）；双格容器锚定基本正确
（±10°）。且打分器本身太弱：最优 yaw 处 IoU 也仅 0.2–0.37 且曲线平坦
（top3 差 <0.01）——凸包轮廓 + 比例失真网格 + 3 个相近视角，不足以可靠
定朝向。

**根因（概念性）**：mix3r 的方向信息在内部存在、`run()` 不导出——
`pipeline_original.py` L377 `pred_c2ws [B,V,4,4]`（每输入视角在对齐后
重建系里的 c2w）与网格同系；L412-414 有被注释掉的导出代码；转台视频用
任意轨道相机渲染。`recenter=True` 预处理又抹掉与原图像素的简单对应。
对下游来说方向属性等效丢失，外部轮廓猜测不可靠。

**修复路线**：不猜——捕获 mix3r 内部 `pred_c2ws`（对
`predict_velocity_points_cams` 做包装捕获，不改 submodule），与 wand
标定的同视角 c2w 做相机对应 Procrustes（中心 Kabsch + 朝向 chordal
均值），闭式解出 mix3r 系→世界系的 R（镜像/yaw 一次性确定）；导出相机
后先自检（网格投影回输入视角对 mask）验证帧一致性与相机质量。

### P3 画面模糊（修，观看参数）

网格数据本身 15–19 万顶点无问题。原因：录制分辨率 1280×720 + viser
自动取景启发式（`radius+0.5m` 兜底）把 0.5m 小场景拉到 ~1.77m 外，
物体仅占画面 ~1/4。修复：小场景取景 + 提高录制分辨率。

### P4 形状（水平比例失真）——**暂不修**（用户决定）

凸包 ≈ 1.5× mask → 初始穿插 → CEM 挪位（layout=1.863 的来源）。已讨论
五条路线，留档备选：

1. **各向异性尺度修正**：多视角 mask 角宽度反推两条水平主轴延展，
   1 DOF 缩放 → 3 DOF（sx,sy,sz）。最小改动、对盒状物准确；前置依赖
   方向修对。**推荐在 P2 修复后首选**。
2. **visual hull 混合**：23+ 标定视角 carve 米制外壳；hull 管尺寸、
   mix3r 管细节，或直接替代。凹结构（把手孔）单侧弧视角下退化。
3. **修 mask + 受控重跑**：lid/handle SAM3 底部渗漏（脚印半径虚增至
   0.32m）同时污染 D 求解与 mix3r 输入；修干净 + 固定视点集/多 seed。
   成本低、全链路受益，但 8-11 证据表明不保证解决比例失真。
4. **物理化解兜底**：现状（CEM 推开），代价 layout 真值被覆盖。
5. **换生成器**：单视角前馈重建 + D 定尺度，超出现计划。

注意 P4 与 P1/P2 独立：方向修好后 IoU 上限仍受形状失真压制。
