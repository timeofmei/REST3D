# mix3r 尺度对齐设计讨论（决策点 C）

日期：2026-08-10（grilling 会话）
状态：**讨论中——已排除 c，b/d 组合方向待实验验证后定案**
相关：`doc/2026-8-10.md`（环境与冒烟记录）、`environments/install_mix3r.md`

## 1. 背景

mix3r 输出的网格是**归一化尺度**（penguin 冒烟结果 bbox ≈ 0.9 单位，原点在物体中心），
而 REST3D Stage 2 现有链路（sam3d → y_align → URDF）产出的是**米制**网格。
mix3r 接入 Stage 2 必须解决"归一化 → 米制"的对齐问题，即决策点 C。

## 2. 事实约束：Stage 3 要求米制（已核实代码）

- `rest3d/utils/urdf.py`：URDF 模板 `<mesh ... scale="1 1 1"/>`，**纯透传**——
  尺度完全由 obj 顶点坐标承载，URDF 无缩放环节。
- `scripts/stable_scene.py`：原样拷贝 `scene_canon_*.obj` + URDF 进 Isaac Gym，
  按 PhysX/URDF 惯例把网格单位当作**米**。
- 稳定门禁是米制阈值（`6/6、0.1 m / 0.1 rad`）——尺度错则门禁语义失效。
- 推论：**最终落到 obj 的必须是米制**；决策点 C 的本质是"对齐基准从哪来"，
  选项 c（归一化直通）已出局。

## 3. 决策点 B（前置决策，已定）

**可切换并行**：`infer_scene3d.py` 增加 `--mesh-backend sam3d|mix3r`，默认 sam3d
不变，mix3r 随时切换。理由：sam3d 是已验证基线；开关式让对比实验零成本。

## 4. 对齐基准选项

| 选项 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| a. sam3d 锚定 | mix3r 模式仍跑 sam3d，只取 `bbox_axes.npz` 米制 bbox 缩放 | 最稳、真值级 | 双倍成本，切换意义减半 |
| b. VLM 尺寸先验 | scene_tree 增加每对象 `size_meters`，按先验缩放 | 零额外模型成本、全覆盖 | 精度依赖 VLM（见 §6） |
| c. 归一化直通 | 不缩放 | — | **出局**：0.9 单位被 PhysX 当 0.9 米 |
| d. 相机几何 | 标定内参 + 支撑面约束反推尺度 | 几何真值、无需 VLM/sam3d | 仅覆盖触地/触面对象；需 mix3r 补丁 |

## 5. 选项 d 的实现流程（若采用）

思路：用"物体底部接触支撑面"约束串起三套坐标：

```
物体帧(归一化) --mix3r 估计相机--> 图像像素 --真实标定相机--> 世界(米制)
```

1. **fork 补丁**：`Pipeline.run()` 导出每视角估计相机（c2w + K）。
   事实已核实：mix3r 内部有 `camera_poses [B,V,4,4] c2w`（`sample_stage_1`），
   但 `run()` 不导出——需在我们 fork 打几行补丁。
2. **按支撑树自底向上递归**（复用 scene_tree 的 `on` 关系）：地面/地板平面
   由标定已知；子对象支撑面 = 父对象缩放后的顶面（故必须先处理父对象）。
3. **每对象闭式解尺度**：mask 底部像素 p → 真实相机射线 → 与支撑面求交 →
   世界坐标 P；对象帧同一接触点 Q 已知（y_align 后网格最低点）；
   缩放 `s ≈ mask 像素高 × 接触点深度 / (f × 对象帧高)`（相机 pitch/roll 可用
   标定修正）。对象世界位姿 = R(up 对齐) + T(P − s·R·Q)。
4. 产出米制 obj，汇入现有 y_align / URDF 链路。

**弱点（必须如实记录）**：

- 接触点必须可由轮廓辨认：椅子/桌子这类"mask 底部 ≈ 接触点"成立；
  **嵌套支撑会破**——人坐椅上时人的可见轮廓底部是腿，不是与椅座的接触点；
- **墙挂/悬空对象**（scene_tree 有 wall 根）无平面接触，d 直接失效；
- mask 底部被遮挡时接触点不可见；
- 实现量约 200 行内，但鲁棒性只覆盖触地/触面子集。

## 6. VLM 尺寸估计的精度讨论（b 方案的核心风险）

### 6.1 现有 VLM 基础设施（已核实）

- 封装：`rest3d/utils/vlm.py` → `generate_vlm_response_gemini()`
- 模型：`gemini-3-flash-preview`（默认；`--vlm-backend` 可选 gpt4o/OpenAI）
- 鉴权：`GEMINI_API_KEY`（仓库 `.env`）；`temperature=0`、max_output_tokens=8192、
  带重试与限流；结果有 fingerprint 缓存
- 调用点：`analyze_scene_tree()`（图 + `rest3d/prompts/list_objects.txt`）
- **现状 prompt 无任何尺寸字段**——尺寸估计是新能力
- b 的两种实现：改现有 scene tree prompt 加 `size_meters`（零额外调用，推荐）
  或单独一次尺寸估计请求（灵活但多 N 次调用）

### 6.2 精度判断（理论 + 社区经验，非本项目实测）

- **信息论事实**：单目 RGB 不包含绝对尺度——"远处大椅子"与"近处小椅子"
  是同一张图。VLM 不能测量，只能：记忆先验（常见物体典型尺寸）+ 场景内
  相对比较（有人 ≈ 1.7 m 参照时显著变准；cam_22 场景恰好有人）。
- **社区经验**：相对判断可靠；绝对米制估计误差普遍 10–30% 量级。
- **对门禁的影响**：尺度误差 20% → 高度差 ~10 cm → 悬空/穿插落在 `0.1 m`
  门禁量级。**结论：无论 VLM 精度如何，裸用 VLM 尺寸不可接受**，必须配
  校正（d）或至少配误差检测（a 作对照）。

## 7. 当前倾向（待实验确认）

**b 为主 + d 校准**：

- b 覆盖所有对象（含嵌套支撑、墙挂），成本最低；
- d 对触地大件（椅子、桌子——恰是尺度误差最致命、VLM 最易错的类别）
  提供几何真值，校验/覆盖 b；
- 两者冲突时以 d 为准并记录告警。

但 b 的精度是**可测事实**，测试成本极低 → 先实验后定案。
