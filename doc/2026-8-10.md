# 2026-08-10 mix3r 适配：分支、子模块与环境决策

## 背景与目标

将 [jsnln/mix3r](https://github.com/jsnln/mix3r)（单图 → 3D 对象网格生成器，基于
TRELLIS + VGGT + Pi3）适配进 REST3D，作为 Stage 2 对象网格生成后端，与
SAM-3D-Objects 并行/可选。全部工作在新分支 `mix3r`（基于 main @ `114eeaa`）上进行。

## 1. mix3r 调研结论（已从源码核实）

- 仓库结构：`mix3r_model/`（150 个 py 文件，vendored TRELLIS/VGGT/Pi3 模块）、
  `run_v1.py`、`run_v2.py`；**无 setup.py / pyproject.toml / requirements**，不是
  pip 包，只能以源码形式存在于目录树。
- **不自包含**：硬 import `cvcg_utils`（`github.com/jsnln/cvcg_utils`，不在 PyPI；
  有 LICENSE；有 setup.py 可 `pip install git+...`）。
- 运行时依赖：sparse 后端默认 `BACKEND=spconv`（可选 torchsparse）；attention 默认
  `ATTN=flash_attn`，`run_v2.py` 显式用 `xformers` 后端；opencv 需 EXR 支持
  （`OPENCV_IO_ENABLE_OPENEXR=1`）；einops/loguru/safetensors（rest3d 已有）。
- upstream `main` 仅 1 个 commit（`8f7505c`），**无 LICENSE 文件**（cvcg_utils 有）。
- 用法：`Pipeline.from_pretrained(mix3r_path=...)` → `pipeline.run(images, out_dir, ...)`，
  输入 RGBA 图像列表，输出写入目录（obj/ply 网格等）。

## 2. 环境决策：为 mix3r 单独建 conda 环境

结论：**单独环境合适**，理由：

1. 项目已有先例：`gym` 环境独立于 `rest3d`（AGENTS.md 多环境政策）；区别只是
   `gym` 被 Python 3.8 强制，mix3r 属于隔离卫生。
2. flash-attn 在 cu128 + sm_120 上通常需源码编译，pip 解析可能升级 torch——
   torch 2.7.1+cu128 是问题 0（doc/2026-8-1.md）好不容易验证的组合，不应冒风险。
3. 进程边界天然存在：mix3r 是 Stage 2 网格生成后端，交接物是文件
   （对象裁剪图 + mask → obj 网格），可作为独立子进程运行；同进程驻留
   SAM3D + VGGT + TRELLIS + Pi3 多个大模型，VRAM（32 GB）也紧张。
4. 隔离上游动荡：单 commit 研究代码，依赖树可能变化，独立环境保证实验失败
   不影响已验证的 Stage 1–2 管线。

注意事项：

- 新环境运行时与 rest3d 相同：**Python 3.11 + torch 2.7.1+cu128**；隔离的只是
  额外包（xformers/flash-attn、cvcg_utils 等），不是另一套运行时。
- 备选方案：先试只装 xformers（不装 flash-attn）进 rest3d，若 pip 解析干净且
  sam3d 回归通过，单环境也成立；但独立环境长期风险收益比更好。

| 包 | 版本 | 来源 |
| --- | --- | --- |
| torch / torchvision | 2.7.1+cu128 / 0.22.1+cu128 | pytorch cu128 index |

### 7.3 关键适配点（sm_120 / Blackwell）

1. **xformers 必须禁用 flash-attn-3 路径**：xformers 0.0.31 的 MEA dispatch 默认优先用内置 flash-attn-3（Hopper sm_90 内核），在 RTX 5090（sm_120）上启动失败（`CUDA error: invalid argument`）。修复：`import xformers.ops.fmha.dispatch as d; d._set_use_fa3(False)`（flash2/cutlass 内核支持 sm_120）。封装进 build 层时必须执行。
2. **utils3d 用错包会静默错在最后一步**：PyPI `utils3d`（0.1.x）无 `.numpy`，报 `module 'utils3d' has no attribute 'numpy'`；EasternJournalist GitHub 版（1.7）才带 `utils3d.numpy`。
3. **diff_gaussian_rasterization_mipsplatting 需要自编译**：TRELLIS 官方及 PyPI 均无此模块名（mip-splatting 官方已改名 diff_gaussian_rasterization）。做法：取 autonomousvision/mip-splatting@dda02ab 的 `submodules/diff-gaussian-rasterization/`，包名/扩展名改为 `_mipsplatting` 后缀后 `pip install --no-build-isolation .`。源码保存在 /home/yangyankun/checkpoints/src/diff-gaussian-rasterization-mipsplatting/（含 Inria 非商用 LICENSE）。
4. **nvdiffrast 不在 PyPI**（404），需 `pip install --no-build-isolation git+https://github.com/NVlabs/nvdiffrast`。
5. **cvcg_utils 的连带依赖**：libigl、plyfile、imageio（video 后端；render.mp4 需 `imageio[ffmpeg]` 可选）。

### 8.2 运行要求澄清（install_mix3r.md 已按此分类）

**正确性必需（每次调用）：**

- `ATTN_BACKEND=xformers`（默认 flash_attn 后端未装 flash-attn 会 ImportError）
- `OPENCV_IO_ENABLE_OPENEXR=1`（必须在 `import cv2` 之前；pipeline 写 EXR 中间文件）
- `_set_use_fa3(False)`（sm_120 必须，其他 GPU 可省但统一禁用无害）
- mix3r 仓库根目录在 `sys.path`（源码消费，非 pip 包）

**性能可选：**

- `SPCONV_ALGO=native`（跳过 spconv 启动基准测试；`auto` 也合法）

这些将在阶段 3 封装进 `rest3d/models/build_mix3r.py`，用户无需手动设置。
